# catalytic-site-decoys

Decoys, baselines and a pre-registered validation set for evaluating methods that compare enzyme catalytic sites.

This repository accompanies the manuscript **“Compactness, not catalytic geometry, drives decoy discrimination in catalytic-site comparison”** (N. Harkiolakis, submitted). It contains all code, input data and per-pair results needed to reproduce every table and figure.

## Main finding

Catalytic-site comparison methods are usually validated by showing that real sites superpose better than randomly chosen residues. Catalytic residues are spatially compact, so this test rewards compactness:

| Method | AUC vs random decoys | AUC vs compactness-matched decoys |
|---|---|---|
| Random one-to-one mapping of the annotated residues (no alignment) | 0.866 | 0.479 |
| Best unrestricted mapping (oracle) | 0.832 | 0.492 |
| Octant-descriptor aligner | 0.846 | 0.507 |
| Side-chain matcher, Cα only, no chemistry | 0.772 | 0.498 |
| Side-chain matcher (Cα + functional groups + chemistry) | 0.818 | **0.685** |

Benchmark of 691 M-CSA enzyme pairs; the pattern replicates on 420 independent pairs. Every method that scores only Cα coordinates is at chance once decoys are matched for compactness. Residue chemistry and side-chain functional-group positions carry the signal that survives.

## Repository layout

```
benchmark/          methods, runners, analyses and per-pair results for the 924-pair benchmark (691 analysable)
  csd/              Cα-trace parsing, local frames, octant descriptor, superposition
  baselines/        Cα baselines on both decoy sets (benchmark and validation)
validation/         independent validation set: selection, leakage filters, results
preregistration/    analysis plan, frozen configuration and byte-identical frozen files, with a fingerprint check
mcsa/               M-CSA curated data snapshot (24 Nov 2026) and derived site, role and EC tables
data_prep/          scripts to download M-CSA data and PDB structures, and to build the site tables
figures/            figures as used in the manuscript
```

PDB structures are not stored; `data_prep/fetch_structures.py` and `validation/fetch_validation_structures.py` download them into `structures/` and `structures_validation/`.

### Method labels used in the code and result files

| Label | Method in the manuscript |
|---|---|
| `v10`, `v11` (`octant_aligner.py`) | octant-descriptor aligner (v10: exact-offset channel only; v11: full method) |
| `dist_only` | distance-only aligner |
| `random_any`, `oracle_mono`, `oracle_any` | random one-to-one, best order-preserving and best unrestricted mappings |
| `v12` (`sidechain_matcher.py`) | side-chain matcher; `v12_ca_only`, `v12_nochem`, `v12_ca_nochem` are its ablations |
| `jess`, `emm`, `emmw` | Jess, Enzyme Motif Miner (residue-restricted) and Enzyme Motif Miner (whole structure) |

Decoy set 1 is generated by `run_decoys.py`; decoy set 2 by `run_v12.py` (also used by `run_jess.py`, `run_emm.py`, `run_v12_ablate*.py` and `run_decoy_baselines.py` with `GEN=v12`). Both are seeded per pair, trial and family.

## Reproducing the results

All runners take `[trials] [workers]` as optional final arguments (5 trials and 2 workers were used). Run benchmark scripts from `benchmark/` and validation scripts from `validation/`.

**1. Data**
```
python data_prep/fetch_structures.py              # -> structures/
python validation/fetch_validation_structures.py  # -> structures_validation/
# optional: python data_prep/fetch_mcsa.py && python data_prep/build_mcsa_sites.py   (mcsa/ already holds the snapshot used)
```

**2. Benchmark: octant-descriptor aligner, same-input baselines, decoy set 1**
```
python run_modec.py ../mcsa/csa_sites.json pairs_924.csv ../structures modec_mcsa_current.csv
python run_experiments.py ../mcsa/csa_sites.json ../mcsa/roles.json pairs_924.csv ../structures exp_mcsa_current.csv
DECOY_MODES=random,surface,spatial,sequence,spatial_seq,composition,compact \
  python run_decoys.py ../mcsa/csa_sites.json pairs_924.csv ../structures decoys_mcsa_current.csv 5
python compute_benchmark_tm.py pairs_924.csv ../structures benchmark_tm.csv
python analyze_benchmark.py                       # BENCHMARK_RESULTS.md, T1–T5, analysis_pairs.csv
```

**3. Side-chain matcher, Jess and Enzyme Motif Miner (decoy set 2)**
```
python run_v12.py  ../mcsa/csa_sites.json ../mcsa/roles.json pairs_924.csv ../structures v12 5
python run_jess.py ../mcsa/csa_sites.json ../mcsa/roles.json pairs_924.csv ../structures jess 5
python run_emm.py  ../mcsa/csa_sites.json ../mcsa/roles.json pairs_924.csv ../structures emm 5
python analyze_v12.py                             # V12_RESULTS.md
```

**4. Validation set** (from `validation/`; selection and threshold are frozen, see `preregistration/`)
```
python ../preregistration/verify_preregistration.py
python leakage_and_strata.py                      # pre-registered %-identity filter, TM strata
python blast_filter.py                            # E-value filter (declared deviation)
python hssp_filter.py                             # HSSP-curve sensitivity analysis
python add_tm.py validation_pairs_blast_noTM.csv validation_pairs_blast.csv
python make_union.py                              # validation_pairs_union.csv
cd ../benchmark
python run_v12.py  ../validation/validation_sites.json ../mcsa/roles.json ../validation/validation_pairs_union.csv ../structures_validation ../validation/val_v12 5
python run_jess.py ../validation/validation_sites.json ../mcsa/roles.json ../validation/validation_pairs_union.csv ../structures_validation ../validation/val_jess 5
python run_emm.py  ../validation/validation_sites.json ../mcsa/roles.json ../validation/validation_pairs_union.csv ../structures_validation ../validation/val_emm 5
python run_experiments.py ../validation/validation_sites.json ../mcsa/roles.json ../validation/validation_pairs_union.csv ../structures_validation ../validation/val_exp.csv
cd ../validation && python evaluate_validation.py # VALIDATION_RESULTS.md
cd ../benchmark && python compare_tools.py        # TOOL_COMPARISON.md
```

**5. Compactness confound across methods, ablations and whole-structure Enzyme Motif Miner**
```
python run_decoy_baselines.py ../mcsa/csa_sites.json pairs_924.csv ../structures baselines/bench.csv 5
GEN=v12 python run_decoy_baselines.py ../mcsa/csa_sites.json pairs_924.csv ../structures baselines/bench_g12.csv 5
python run_decoy_baselines.py ../validation/validation_sites.json ../validation/validation_pairs_union.csv ../structures_validation baselines/val.csv 5
GEN=v12 python run_decoy_baselines.py ../validation/validation_sites.json ../validation/validation_pairs_union.csv ../structures_validation baselines/val_g12.csv 5
python run_v12_ablate.py  ../mcsa/csa_sites.json ../mcsa/roles.json pairs_924.csv ../structures v12abl 5
python run_v12_ablate2.py ../mcsa/csa_sites.json ../mcsa/roles.json pairs_924.csv ../structures v12abl2 5
python run_v12_ablate.py  ../validation/validation_sites.json ../mcsa/roles.json ../validation/validation_pairs_union.csv ../structures_validation val_v12abl 5
python run_v12_ablate2.py ../validation/validation_sites.json ../mcsa/roles.json ../validation/validation_pairs_union.csv ../structures_validation val_v12abl2 5
python run_emm_whole.py ../mcsa/csa_sites.json pairs_924.csv ../structures emmw_bench 1
python run_emm_whole.py ../validation/validation_sites.json ../validation/validation_pairs_union.csv ../structures_validation emmw_val 1
python analyze_decoy_baselines.py                 # DECOY_BASELINES.md, T_decoy_baselines.csv
python analyze_v12_ablate.py                      # ABLATION_DECOYS.md, abl_results.json
python analyze_emm_whole.py                       # EMM_WHOLE.md

python make_figures.py ../figures                 # Figures 1–3
```

## Pre-registration

`preregistration/PREREGISTRATION.md` and `preregistration/FROZEN_CONFIG.json` were written before any validation structure was downloaded. `FROZEN_CONFIG.json` records SHA-256 fingerprints of the code, parameters, threshold and pair lists. Byte-identical copies of those files are in `preregistration/frozen_files/`; `python preregistration/verify_preregistration.py` checks them. The paths inside `FROZEN_CONFIG.json` and the frozen files are those of the working tree at the time of freezing. The working copies elsewhere in the repository differ from the frozen files only in module names and paths, and give identical results.
